# Rick and Morty

Это демонстрационный проект: каталог персонажей Rick and Morty с поиском и экраном персонажа.

Само приложение простое, главное в нём — подход. Здесь собрана концепция и архитектура, по которым я строю свои проекты.

## Как я строю проекты

**Feature-first + Clean Architecture.** Каждая фича — самостоятельный модуль со слоями `data`, `domain`, `presentation`. Domain написан на чистом Dart и ничего не знает ни о Flutter, ни о сети. Data реализует интерфейсы domain, а presentation работает только через usecase'ы и сущности.

**Экран из четырёх частей.** `Screen` только собирает дерево. `ScreenScope` создаёт BLoC и его зависимости. `ScreenListener` отвечает за побочные эффекты: snackbar, навигацию. `Layout` — сам UI.

**BLoC и явная конкурентность.** Для каждого события задаю режим обработки: поиск идёт через debounce + restartable, пагинация и refresh через droppable. Ответы на устаревшие запросы отбрасываются.

**DI без сервис-локаторов.** Глобально живёт только инфраструктура: HTTP-клиент и роутер. Репозиторий, usecase и BLoC создаются в `ScreenScope` своего экрана и живут вместе с ним.

**Никакого хардкода в UI.** Цвета и размеры берутся из темы (`AppTheme`), строки из локализации (`AppLocalizations`).

**Дисциплина кода.**
- Один класс — один файл; виджеты пишу отдельными классами, а не методами `_buildXxx()`.
- Имена говорят сами за себя, поэтому комментариев нет.
- Данные из API типизирую через `Object?`, не `dynamic`.
- Строгий набор правил анализатора; `flutter analyze` всегда чистый.
- Сгенерированный код хранится в репозитории.
- Версия Flutter закреплена через fvm.

**Тесты на логику.** Unit-тесты покрывают BLoC'и и репозиторий.
